01 项目定位 解决什么问题 · 给谁用
现有方案的痛点
  • 纯正则 DLP：误报高，4111111111111111 到底是卡号还是随机数？
  • 纯大模型识别：单条 2-5 秒，线上跑不动；还要求把原文送出本机
  • 一刀切封堵：业务不可用，低危信息（IP、示例邮箱）也被拦
  • 企业级 DLP 太重：多租户、集中策略下发，个人与小团队用不起
FlowMask 的取舍
  • 规则保证吞吐：L1 全量毫秒级扫描，绝大多数流量直接判 SAFE
  • 模型保证准确：L2 BERT + L3 本地大模型只复核可疑样本
  • 分级决定处置：L3 全屏蔽 / L2 部分遮掩 / L1 警示 / SAFE 放行
  • 轻量本地闭环：Python FastAPI 一体机，SQLite 默认存储，数据不出机

级别处置示例说明

L2保留首字符 + 星号13800138000 → 1******手机、邮箱、地址等中危

六种导出策略（导出时按需选择）

partial 部分遮掩
保留首字符 + 星号，保留可读性，适合临床数据共享、教学演示。
block 全屏蔽
整体替换为 [已屏蔽:类别]，最彻底，适合日志归档、对外发布。
hash 哈希替换
SHA256 哈希，彻底去标识化且可比对，适合政务公开、去重统计。
generalize 数值泛化
数值型字段做区间泛化（如年龄 28 → 20-30），保留统计特征。
pseudonym 假名替换
用假名替代真实姓名，保留订单结构，适合风控分析、外包交付。
encrypt AES-GCM
强加密可逆，密钥随文件返回不持久化，适合金融流水、需还原场景。

支持按原文格式重建导出：text / json / csv / sql / docx / pdf；原文不落库，同请求内重建。

06 多模态 OCR 图片识别 · 轻量专用视觉模型
实现方式
使用 rapidocr-onnxruntime（ONNX 格式轻量专用视觉模型），不调大模型，速度快、本地运行。
支持上传 .png / .jpg / .jpeg，OCR 解析为文本后走同一套识别分级链路。
懒加载与开关
引擎模块级懒加载，首次调用才初始化；默认关闭，需在服务端设置 FLOWMASK_OCR_ENABLED=1 并安装 rapidocr-onnxruntime 后生效。
关闭时上传图片返回 415，提示用户启用。
07 检测记录 · 审计哈希链 自动留痕 · 篡改可见
检测自动建记录
内容检测页每次检测（文本或文件）自动创建一条检测记录，记录里包含输入哈希、命中的规则、操作人、生成时间。
检测记录页只负责展示与导出，不需要手动提交。
HMAC-SHA256 哈希链
所有审计记录通过 prev_hash / signature 串成链，任何一条被篡改都会在校验时被发现，并定位断点位置。
支持隐私导出（差分隐私 + l-多样性）、JSONL / CSV / JSON / SQL 多格式导出。
#1 input_hash: a3f2...c81b → prev: (genesis) → sig: 9e2d...f41a
#2 input_hash: 7c1b...e093 → prev: 9e2d...f41a → sig: 2a8f...c015
#3 input_hash: b5e4...1d2a → prev: 2a8f...c015 → sig: 6f17...ab03
#4 input_hash: 0c8a...f7e1 → prev: 6f17...XX → sig: 校验失败 · 断点 #4
08 隐私增强导出 差分隐私 · l-多样性
差分隐私（Laplace 噪声）
ε 控制加噪强度：数值越小噪声越大、越难反推个体，但统计越模糊；数值越大越接近真实数据。
一般从 1 开始，需要更强保护调到 0.5 以下，需要更准的统计调到 2 以上。
l-多样性检查
l 要求每组至少有 l 条不同记录才输出：l 越大越难反推个体，但可能因分组不满足而告警。
常用 2-5；导出时给出 l-多样性报告，不满足的分组会标出。
